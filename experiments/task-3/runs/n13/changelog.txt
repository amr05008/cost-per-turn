On a weak/dropped connection the app fired a single request with no
pre-flight check and surfaced generic "Request timed out / Network error"
copy — which reads as "the app is broken." Worse, when the server completed
a scan but the response didn't reach the phone in time, the user saw a
failure for a scan that actually succeeded, with no hint it was their
connection. (Root-caused from a real 2026-07-11 report: a client timeout at
21:32:53 + the device's IP-derived id changing between the failing and
working sessions = unstable network; backend was healthy throughout.)

- Add a pre-flight connectivity check (expo-network) to both the OCR and
  barcode paths: fail fast and clearly when offline instead of hanging
  30-60s for a request that can't land.
- Reword network/timeout messages to name the connection, so a transient
  blip stops reading as an app failure.
- Never let the connectivity probe itself block a scan (probe error or
  unknown reachability falls through to the real request).
- Remove a stray, unimported services/api 2.ts duplicate.
