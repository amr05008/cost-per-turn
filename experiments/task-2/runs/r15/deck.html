Internal PM Session

Go get yourself a personal agent

An always-on assistant you can reach from anywhere — and why it's the most useful thing I've built this year.

Speaker notes

Open with the pitch: of all the fun and wild stuff I've explored this past year, personal agents are the most useful, the most interesting, and now the foundation I layer new projects on top of. Having an always-on, super-helpful assistant reachable from my computer, phone, wherever, has changed how I use the internet. This talk is my argument that you should build one too.

The Setup

At a glance

  • Two always-on agents: "Pi Pi" on a Raspberry Pi 5, "Agent M1" on an old laptop
  • One shared memory layer, synced through GitHub every few hours
  • Reached entirely from Discord — phone, laptop, anywhere
  • Runs inside a Claude Max plan, plus API costs for side projects

Speaker notes

Give the audience the mental model up front: cheap always-on hardware, Discord as the interface, GitHub as shared memory, and a subscription most of us already have. Emphasize this is achievable with commodity hardware — a $80 Pi or a dusty old laptop — not a data center.

How It Works

Claude Channels: wire a Claude Code session to a messenger

The agent lives in an always-on Claude Code session. A plugin listens to a messaging channel (Discord DM or channel post), forwards messages to the agent, and the agent replies right in the chat.

No SSH, no special client — you just message it like a coworker.

Speaker notes

Explain the mechanism simply: the Claude Channels plugin bridges a messaging API and a Claude Code session. My first experience with an always-on agent was Openclaw — powerful but frustrating to keep running. Channels gave me the same always-on reachability on top of tooling I already trust. The agent lives somewhere always-on (my first one, Pi Pi, runs on the same Pi 5 I used for Openclaw), so it's reachable at any time.

The First Agent

Pi Pi: every thought becomes a plan

  • Voice-to-text from my phone — no need to be precious about wording
  • Best ideas happen biking or walking the dog; the phone is the capture device
  • The agent researches, writes a markdown plan, commits it to git
  • I pick it up from my laptop later and execute — or delegate it back to the agent

Speaker notes

The single most useful workflow: turn random ideas into plans. Before this, I'd email ideas to myself, scribble them on paper, or dump them into Notion — forgotten and never revisited. Now a lot more of my silly ideas become high-fidelity plans I actually take on, delegate, or deliberately archive. Note for PMs: sloppy voice-to-text input is fine — Opus/Sonnet parse intent well. This is the "idea capture → spec" loop PMs do manually, automated.

Organizing the Work

Discord channels = job segmentation

#questions / #reminders / #to-do

Dump questions, schedule reminders, assign tasks

#daily-briefing / #signals

Weather + authors I follow; twitter-watcher summaries

#inbox-alerts

Agent flags emails that need attention

#fitness / #glutenornot

Zwift race analysis via Strava; uptime + Sentry alerts for my app

Start with one #general channel. Add channels one at a time, mostly per-project.

Speaker notes

I started with just #general and layered channels on one at a time — strongly recommend starting small. Each channel is a job queue or feed with a dedicated purpose. PM framing: this is like spinning up a Slack channel per workstream, except the other participant is an agent that never sleeps. The channel becomes the API contract between me and the agent.

The Big Shift

Information flows to me — I stop wading through the internet

  • inbox-watcher: reviews, catalogs, and prioritizes forwarded email; flagged a rescheduled Rosalía concert at MSG before I'd ever have noticed
  • twitter-watcher: reads topics/accounts, decides what's worth reading, posts a weekday summary to #signals
  • Agents share channels, so I can task Pi Pi to dig deeper on anything that shows up

Speaker notes

I used to check email incessantly and absentmindedly. The inbox-watcher breakthrough: I have gmail inboxes forwarded to the agent and only get pinged in #inbox-alerts when something needs action — like the concert reschedule, no inbox-zero chasing required. Twitter-watcher: I wanted Twitter's information without spending time on Twitter. Compounding example: a #signals post mentioned Claude Tag; I tasked Pi Pi to research how people use it and report back — I never logged into Twitter. For PMs: this is moving from pull to push for information, with an agent as the filter.

Build It

Setup: learn from my mistakes

  • Any always-on machine works — a Pi is cheap and low-power, but an old laptop is fine
  • Skip systemd services — run the session in tmux wrapped in a while true loop so it respawns on crash
  • loginctl enable-linger so the session survives SSH disconnects
  • Tailscale for a private tailnet between your devices — "a secure conference room" off the public internet
claude --channels plugin:discord@claude-plugins-official

Speaker notes

War story: I first set up the Pi session as a systemd service with auto-restart — it broke multiple times in the first few hours. With guidance from Opus I swapped to tmux + while-true, and it's been solid. I'd heard of tmux from Steve Yegge's Gas Town writeup and figured it was time to try. Enable user lingering or the tmux session dies when you disconnect SSH. Tailscale makes SSHing into the Pi and other devices trivial. Tools/skills/MCPs are configured exactly like a normal Claude Code session — SSH in, attach to tmux, connect what you need. Both agents have read access to my GitHub so they understand my projects in flight.

Scaling Up

One agent → two: Agent M1 joins

  • Lives on an old laptop: more power for research, more storage, room to experiment with local LLMs
  • More responsibility: write access to my GlutenOrNot app, Sentry + Posthog MCPs, reviews/submits PRs with guardrails
  • Shared memory in GitHub: each agent syncs every ~4 hours, both read the same memory — one brain(ish)
  • Real moment: Agent M1 debugged an EU app-store issue while Pi Pi handled finance questions — concurrently, from my phone

Speaker notes

The Pi is still going strong; the second agent was part tinkering, part capability tiering. The laptop agent gets the trust-sensitive jobs (app write access, Sentry/Posthog) with explicit guardrails on autonomous action. The shared memory layer is the key trick: agents sync memory to GitHub every ~4 hours and read across the same store, so what one learns, the other knows. There's a great image in the full writeup of Agent M1 reviewing a PR that Pi Pi created — agents collaborating on my app while I'm away from my desk.

Learnings

Three hard-won lessons

  • Real memory, not just a session. Less is more — only critical rules and active-project facts load every session; the rest is on-demand or archived.
  • Take security seriously. Agents see untrusted input (emails, Sentry errors). Minimal tool access, audit allow-lists after week one, hardware keys on important accounts.
  • You will tinker. Not zero overhead: ~2 restarts in 3 months, weekly /clear of the 1M-token context. Fits in a $100 Claude Max plan.

Speaker notes

Memory: everything in memory loads into context every session, so if it grows too big the agent misses the important stuff in the noise — curate ruthlessly. Security: my channel agents have far less access than my desktop sessions because untrusted content flows through them; they must never act on instructions embedded in emails or error messages, and never approve new access without my direct say. Start restrictive, grant more as trust builds — otherwise the agent DMs you for permission constantly. Maintenance reality: silent failures happen (check the tmux session if Discord goes quiet), auth occasionally drops, and I clear the context window weekly. Cost: fine within the $100 Max plan; side projects like twitter-watcher use API keys with variable cost.
