Go get yourself a personal agent

The most useful thing I built this year — and the foundation I now layer every new project on top of.

Open with the core pitch: of everything I explored this past year, personal agents are the most useful and most interesting. Frame it as a changed relationship with the internet — an always-on assistant reachable from my computer, phone, anywhere. Promise: by the end, they'll know exactly how to build one themselves.
The setup

Two agents, one brain, reachable from anywhere

  • Pi Pi — always-on agent on a Raspberry Pi 5
  • Agent M1 — second agent on an old laptop, more power & access
  • Shared memory layer, synced through GitHub every ~4 hours
  • Reached entirely from Discord — phone, laptop, anywhere
  • Runs on a Claude Max plan ($100 tier) + API keys for side projects
Give the 30-second architecture tour before any details. Emphasize how cheap this is: a Pi 5, an old laptop gathering dust, a Discord server, and a subscription many already have. No exotic infra. Note the memory sync: the source doc says ~4 hours between the two agents. Keep this slide quick — it's a map, not the territory.
How it works

Claude Channels: a Claude Code session wired to a messenger

  • The agent lives in a Claude Code session on an always-on machine
  • The Channels plugin listens to a messaging API (I use Discord)
  • DM or channel post → forwarded to the agent → reply appears in the chat
  • No SSH, no being at your desk — the agent is just always there
$ claude --channels plugin:discord@claude-plugins-official
# or find it via the "Discover" tab in /plugins
Explain the mechanism simply: instead of being tied to your terminal, the Claude Code session listens to Discord. My prior attempt was Openclaw — my first taste of an always-on agent that remembers you, but it needed constant repair. Claude Channels gives the same magic on tooling I already trust. Tools, skills, and MCPs attach the same way as any Claude Code session — SSH in, open the tmux session, configure as usual.

  • The killer workflow: agent researches the idea, writes a markdown plan, commits it to git
  • I pick it up later from my laptop and execute — or delegate it back to the agent

This is the emotional heart of the talk. My best ideas come while biking or walking the dog — previously they evaporated. For PMs: think of it as a capture-to-spec pipeline with zero friction at the capture end.
Organizing the work

Discord channels = job segmentation

Started with just #general. Added channels one at a time, mostly per-project. Start small.

#questions #reminders #daily-briefing #signals #inbox-alerts #to-do #fitness #glutenornot
Walk a few examples: #daily-briefing gets weather + articles from authors I follow each morning; #signals gets the twitter-watcher digest; #inbox-alerts gets flagged emails; #fitness analyzes Zwift races from Strava URLs; #glutenornot gets uptime and Sentry alerts for my app. Key advice for the room: resist building the whole taxonomy up front — start with #general and add channels only when a real job shows up.

How to set it up

Learn from my mistakes

  • Any always-on machine works — a Pi is cheap & low-power, but an old laptop is fine
  • Use tmux, not systemdMy systemd service broke repeatedly within hours; tmux + a while-true loop just respawns the agent
  • loginctl enable-linger so the session survives SSH disconnects
  • Tailscale for a private tailnet — easy, secure SSH into all your devices
  • Agents get my GitHub access so they can read across all my repos and projects
Practical slide — slow down here if the room is technical. The systemd-vs-tmux lesson: I tried to run Claude Code as a proper systemd service with auto-restart, it broke multiple times in the first hours, and Opus itself suggested tmux (which I'd first heard about via Steve Yegge's Gas Town post). Don't forget linger or the tmux session dies when you disconnect. Tailscale is genuinely great — a "secure conference room" for your devices, nothing exposed to the public internet.
Scaling up

From one agent to two

  • Agent M1 on an old laptop: more compute for research, more storage, local-LLM experiments
  • M1 gets more responsibility: write access to my GlutenOrNot app, Sentry & Posthog MCPs, PR review with guardrails
  • Shared memory in GitHub: both agents sync every ~4 hours and read the same memory — one brain(ish)
  • Real session: M1 debugged my app's EU availability while Pi Pi handled finance questions — concurrently, from my phone
A fun concrete image: Agent M1 reviewing a PR that Pi Pi created to debug API failures on my app — agents collaborating. The EU story: GlutenOrNot wasn't showing up in the EU; M1 helped me figure out I hadn't signed the right forms, while Pi Pi concurrently helped with finance questions, all while I was away from my computer. The shared GitHub memory is what makes two agents feel like one system.
Learnings

Three things that matter

  • Give it a real memory, not just a sessionLess is more — everything in memory loads into context. Load only critical rules + active projects; archive the rest.
  • Take security seriouslyChannel agents get far less tool access than my desktop sessions. They see untrusted input (emails, Sentry errors) — no acting on embedded instructions. Audit allow-lists after week one; expand as trust grows. Hardware keys on important accounts.
  • You will need to tinkerNot zero overhead: ~2 restarts in 3 months, plus a weekly /clear of the 1M-token context window. If it goes quiet on Discord, it's silently failing — check the tmux session.
This is the PM-credibility slide — honest tradeoffs. Memory: co-design it with the agent; noise in context means it misses the important stuff. Security: blast radius scales with tools + permissions; agents process untrusted content, so prompt-injection discipline matters. Start restrictive, audit after a week or two, then expand — otherwise you'll get constant permission DMs. Maintenance is real but small: two restarts in three months on the $100 Max plan, weekly context clears. Side projects like twitter-watcher use API keys with variable cost.
