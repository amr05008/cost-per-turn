Internal PM session · 20 min

Go get yourself a
personal agent

Two always-on agents — Pi Pi on a Raspberry Pi 5, Agent M1 on an old laptop. One shared memory, synced via GitHub. Reached entirely from Discord, from my phone or laptop, anywhere.

Opening (1 min): This is a show-and-tell, not a product pitch. Everything I show today is running on my own hardware, inside a Claude Max plan plus some API costs for side projects.

The claim up front: of everything I've tinkered with this past year, personal agents are the most useful thing I've built — and now the foundation I layer new projects on top of. By the end I want you to believe this is buildable by anyone in this room.

The pitch

An always-on assistant, reachable from anywhere, changed how I use the internet.

  • Thoughts, ideas, questions, tasks — sent the moment they happen
  • Most interesting ideas arrive while biking or walking the dog
  • Voice-to-text on my phone is the main interface — no precision required

(2 min) The behavior change matters more than the tech. Before this, I emailed ideas to myself, scribbled on paper, dumped things into Notion — mostly forgotten, never revisited.

Now a rough voice memo is enough. If you're running Opus or Sonnet underneath, the agent parses sloppy dictation fine. Don't be precious about what you hit send on. The bar for capturing an idea dropped to nearly zero — and that's the whole point.

The mechanism

Claude Channels: a Claude Code session wired to Discord

  • Agent lives in a Claude Code session on an always-on machine
  • Plugin listens to the messaging API — a DM or channel post
  • Message is forwarded to the session → agent replies in the chat
  • My first agent, Pi Pi, runs on the same Raspberry Pi 5 I used for Openclaw

(2 min) Context: Openclaw was my first taste of an always-on agent that learns and recalls my preferences. Powerful, but I spent a lot of time repairing it — there's a writeup on my blog about that frustration.

Claude Channels gets me the same always-on reach with far less maintenance. Key concept for PMs: the messaging app becomes the client. I never SSH in to talk to the agent — Discord on my phone is the UI.

The killer workflow

Random idea → researched plan in git

  • Send Pi Pi whatever idea I have, mid-walk, mid-anything
  • It doesn't just start building — it researches first
  • Writes a markdown plan → committed to a plans folder in git
  • I pick it up later from my laptop and execute when ready

Result: more silly ideas become high-fidelity plans — executed, delegated to the agent, or deliberately archived.

(2.5 min) This is the single most useful workflow I've found, so slow down here. The insight: the agent's job isn't just answering, it's converting fleeting thoughts into durable, actionable artifacts.

Three possible outcomes per idea, all fine: I execute it, I delegate it to the agent, or I throw it away on purpose instead of forgetting it by accident. For a PM audience, frame this as an idea pipeline with a real triage step.

Organizing the work

Discord channels = job segmentation

#questionsDump random questions
#remindersSchedule & receive reminders
#daily-briefingWeather + articles from authors I follow
#signalsDaily twitter-watcher summaries
#inbox-alertsAgent flags emails needing attention
#to-doAssign agent tasks
#fitnessZwift race analysis via Strava MCP
#glutenornotUptime alerts + Sentry errors for my app

Started with just #general. Add channels one at a time, mostly per-project. Start small.

(2 min) Don't present this as a blueprint to copy — it's what accreted over months. The advice: start with #general, add a channel only when a job shows up repeatedly.

Note the pattern: each channel is a queue with a purpose. Some are inbound (alerts flow to me), some are outbound (I assign work). That separation is what keeps the system calm instead of noisy.

The behavior shift

Information I want flows into my Discord. I stopped wading through the internet to find it.

  • inbox-watcher reviews, catalogs, prioritizes forwarded email — flagged a rescheduled Rosalía concert at MSG before I'd have seen it
  • twitter-watcher reads topics/accounts I care about, posts weekday summaries to #signals — Twitter signal without Twitter time
  • Pi Pi lives in the same channels, so I can say "go deeper on that" and it brings back more

(2.5 min) The Rosalía story is the concrete win — tell it. Concert rescheduled, agent caught it in a forwarded email and flagged it as action-required, without me watching email or chasing inbox zero. I still check email sometimes, but far less.

The compounding part: because Pi Pi is present in the same channels where webhook agents post, I can task it conversationally — e.g. "find out how people are using Claude Tag" to complement a #signals post — without ever logging into Twitter.

Standing it up

Setup: boring on purpose

  • Any always-on machine. Raspberry Pi: cheap, low power. An old laptop works fine.
  • Skip systemd services — mine broke within hours. Run the session in tmux, wrapped in a while true loop so it respawns after crashes or /exit
  • loginctl enable-linger so tmux survives SSH disconnects
  • Tailscale for a private tailnet — a "secure conference room" for your devices
claude --channels plugin:discord@claude-plugins-official

(2.5 min) "Learn from my mistakes: just go with tmux." I first tried systemd with auto-restart; it broke repeatedly in the first few hours, and Opus itself suggested tmux — I'd heard of it from Steve Yegge's Gas Town writeup.

Tools, skills, MCPs get added exactly like a normal Claude Code session: SSH in, open the tmux session, configure. Both agents have read access to my GitHub so they understand my projects in flight. Also discoverable via the /plugins "Discover" tab.

Scaling up

One agent → two agents, one shared brain

  • Agent M1 on an older laptop: more power for research, more local storage, room to experiment with local LLMs
  • M1 gets more trust: read/write on GlutenOrNot, Sentry + Posthog MCPs, submits PRs — with guardrails
  • Shared memory layer in GitHub: each agent syncs every ~4 hours, both read the same memory
  • From my phone: M1 debugged why GlutenOrNot wasn't showing in the EU while Pi Pi worked through finance questions — concurrently

(2 min) If there's a screenshot available, this is where the "Agent M1 reviewing Pi Pi's PR" image goes — agents reviewing each other's work is the moment the room leans in.

The memory sync detail: ~4-hour sync cadence to GitHub, both agents read across it. "One brain (ish)." The concurrent-session story shows the real payoff: parallelism from a single phone while away from my desk. The EU issue turned out to be unsigned forms — a mundane bug an agent chased down.

Hard-won lessons

Three learnings

  • Real memory, not just a session. Everything in memory loads into context — less is more. Load only critical rules + active projects; archive or recall the rest on demand.
  • Take security seriously. Channel agents get far less tool access than my desktop sessions. They see untrusted input (emails, Sentry errors) — they must never act on embedded instructions. Audit allow-lists after week one; widen permissions as trust grows. Hardware keys on important accounts.
  • You will tinker. Not Openclaw-level repair, not zero overhead. Two restarts in 3 months; /clear the 1M-token context weekly. Fits inside a $100 Claude Max plan; side projects use API keys at variable cost.

(3 min) This is the credibility slide — spend real time here.

Memory: bloat kills recall; the agent misses important stuff in the noise. Work with your agent to design the system.

Security: blast radius framing lands well with PMs. Untrusted content is a prompt-injection surface. Start restrictive; I granted more over time because the agent was DMing me for permission on things I was comfortable with (like reading a repo).

Maintenance reality: if the agent goes quiet on Discord, it's usually a silent failure or dropped auth — SSH in, check tmux, restart. Cost question always comes up: $100/mo Max plan covers channels; API-key projects are extra and variable.

Where this goes

What's next

  • Reduce single-vendor reliance: OpenRouter so agents stay online if Claude goes down
  • Local models for private data — financials, email — instead of cloud frontier models
  • Personal agents are here to stay. This is a better way of using the internet, and I don't want to go back.
