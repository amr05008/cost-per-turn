Go get yourself a personal agent

Always-on AI assistants that changed how I use the internet — and why you should build one too

Speaker notes

Of all the fun and wild stuff I explored this past year, personal agents are the most useful, the most interesting, and now the foundation I layer new projects on. Having an always-on, super helpful assistant reachable from my computer, phone, wherever — has genuinely changed how I use the internet. This talk: what I built, how it works, what I learned, and how you can start.

The setup at a glance

  • Two always-on agents: "Pi Pi" on a Raspberry Pi 5, "Agent M1" on an old laptop
  • One shared memory layer, synced through GitHub
  • Reached entirely from Discord — phone, laptop, anywhere
  • Runs inside a Claude Max plan ($100 tier), plus API costs for side projects

Speaker notes

Key point: this is not exotic hardware or a big budget. A ~$80 Raspberry Pi and a retired laptop. The total ongoing cost fits inside the Claude Max plan I already pay for. The unlock isn't money, it's deciding to set it up.

How it works: Claude Channels

  • Channels wire a Claude Code session to a messaging channel (I use Discord)
  • The agent listens for new messages — a DM, or a post in a channel it's in
  • It crafts a reply and responds right in the chat
  • Because the session lives on an always-on machine, the agent is reachable anytime, from anywhere

Speaker notes

My first always-on agent experience was Openclaw — promising but frustrating. Claude Channels is the same idea, far more reliable. No SSHing in, no being at your desk. You just message it like a coworker. My first agent, Pi Pi, runs on the same Pi 5 I used for Openclaw.

Pi Pi: my idea-capture machine

My best ideas arrive while biking or walking the dog. Now I voice-text them to Pi Pi, and they come back as researched, written plans — committed to git — instead of dying in my inbox.

Speaker notes

Don't be precious about voice-to-text accuracy — Opus/Sonnet parse sloppy input fine. The killer workflow: agent researches the idea, writes a markdown plan into a plans folder, commits to git. I pick it up from my laptop later and execute. Before this: emails to self, scraps of paper, Notion graveyard. Now far more silly ideas become high-fidelity plans — executed, delegated to the agent, or consciously archived.

Discord channels = job segmentation

  • #questions — random questions, dumped
  • #reminders — schedule & receive reminders
  • #daily-briefing — weather + articles from authors I follow
  • #signals — daily twitter-watcher digests
  • #inbox-alerts — flagged emails that need me
  • #to-do — assign agent tasks
  • #fitness — Zwift race analysis via Strava
  • #glutenornot — uptime & Sentry alerts for my app

Started with just #general. Layered channels on one at a time, mostly per-project. Start small.

Speaker notes

Each channel is a context boundary — the agent knows what a #reminders message means versus a #to-do message. Resist building 10 channels on day one; add them as real needs emerge. This structure is what makes a single agent feel like a team of specialists.

Information flows to me now

  • Inbox-watcher: reviews, catalogs, and prioritizes forwarded email — flagged a rescheduled Rosalía concert at MSG before I'd have ever seen it
  • Twitter-watcher: follows topics and accounts, judges what's worth reading, posts a weekday summary — I get Twitter's value without opening Twitter
  • Agents compose: I tasked Pi Pi to research Claude Tag usage to expand a #signals post — without ever logging in

Speaker notes

The inversion: I used to wade out into the internet (compulsive email checking) — now dedicated agents push me only what matters. The Rosalía example lands well: real money and a real event saved with zero vigilance on my part. And because personal agents sit in the same channels as the watcher agents, I can task them to go deeper on anything that surfaces.

Setting it up (learn from my mistakes)

  • Any always-on machine works — old laptop is fine, Raspberry Pi is cheap + low power
  • systemd auto-restart broke repeatedly → tmux + a while true loop respawns the agent if it crashes
  • loginctl enable-linger so tmux survives SSH disconnects
  • Tailscale for a private, secure network between your devices
claude --channels plugin:discord@claude-plugins-official

Speaker notes

Three hard-won lessons in one slide. (1) Skip systemd — just go tmux with a while-true wrapper. (2) Enable user lingering or your session dies when you disconnect SSH. (3) Tailscale makes reaching the Pi trivial and secure. Tools/skills/MCPs get added exactly like a normal Claude Code session — SSH in, open tmux, configure. Both my agents can read across all my GitHub repos.

One agent → two agents

Agent M1 (old laptop)

More power and storage. Write access to my GlutenOrNot app, Sentry + Posthog MCPs — detects issues, reviews and submits PRs with guardrails. Even reviews PRs created by Pi Pi.

Shared memory

Both agents sync memory to GitHub every ~4 hours and read across the same store. If one learns something, the other picks it up. One brain (ish).

One session from my phone: M1 debugged why my app wasn't showing in the EU (unsigned forms) while Pi Pi handled finance questions — concurrently.

Speaker notes

The second agent wasn't about need — I wanted to tinker and had the hardware. But the multiplier is real: more responsibility where there's more trust, and the shared GitHub memory layer means they compound each other's learning. The phone anecdote shows the end state: parallel, specialized help from your pocket.

Three learnings

  • Give it real memory, not just a session. Less is more — everything in memory loads into context. Load only critical rules/active projects; archive the rest.
  • Take security seriously. Agents see untrusted input (emails, error reports). Minimal tool access, audit allow-lists after week one, hardware keys on important accounts. Expand permissions as trust grows.
  • You will tinker. Not zero-overhead, but low: ~2 restarts in 3 months, weekly /clear of the context window. Fits in the $100 Claude Max plan.

Speaker notes

Memory: bloated memory means the agent misses the important stuff in the noise — treat it as curated, on-demand context. Security: think blast radius. Never let agents act on instructions embedded in untrusted content or approve access requests not directly from me. Maintenance reality: if the agent goes quiet on Discord, it's usually auth or a silent crash — SSH in, restart in tmux. Total upkeep is minutes per week.

What's next — and your move

  • Reducing single-model reliance: OpenRouter fallback so agents stay up if Claude goes down
  • Local models for private data — financials, email — instead of cloud frontier models

Personal agents are here to stay. This is a better way of using the internet — and I don't want to go back.
