Go get yourself a
personal agent

An always-on assistant you can reach from anywhere — and why it's the most useful thing I've built this year.

Opening: of all the fun and wild stuff I've explored this past year, personal agents are the most useful, the most interesting, and now the foundation I layer new projects on top of.

Having an always-on, super helpful assistant accessible from my computer, phone, wherever, has changed how I use the internet. By the end of this talk I want you to believe you should build one too.

The setup, at a glance

  • Two always-on agents: "Pi Pi" on a Raspberry Pi 5, "Agent M1" on an old laptop
  • One shared memory layer, synced through GitHub every ~4 hours
  • Reached entirely from Discord — phone, laptop, anywhere
  • Runs inside a Claude Max plan, plus API costs for side projects

Give the audience the map before the tour. Pi Pi is the original agent on a cheap, low-power Raspberry Pi. Agent M1 is newer, on an old laptop with more power and storage.

Key point: none of this is exotic hardware. A Pi is cheap; an old laptop you already own works fine.

How it works: Claude Channels

Claude Channels wire a Claude Code session to a messaging channel — so the agent lives on an always-on machine, and you talk to it from Discord.

you (Discord DM) → channel API → agent listens → crafts reply → back in chat

Mechanics: the plugin has the agent listen to the messaging channel's API for new messages — a DM or a post in a channel the agent is in. It forwards the message to the always-on session, the agent replies right in the chat.

My first always-on agent experience was Openclaw; Claude Channels gave me the same always-available feel inside a normal Claude Code session. Pi Pi runs on the same Pi 5 I first used with Openclaw.

The killer workflow: idea → plan

  • Every thought, idea, question, or task goes to the agent — usually voice-to-text from my phone
  • Best ideas come while biking or walking the dog — capture before they disappear
  • The agent doesn't just start building: it researches, writes a markdown plan, commits it to git
  • I pick it up from my laptop later and execute — or delegate, or archive

Don't be precious about voice-to-text accuracy — with Opus or Sonnet underneath, the agent parses what you meant.

Contrast with before: emailing myself ideas, scribbling on paper, dumping into Notion — forgotten and never revisited. Now silly ideas turn into high-fidelity plans I actually take on, delegate, or deliberately throw away.

Discord channels = job segmentation

#questions — random questions
#reminders — scheduled reminders
#daily-briefing — weather + articles from authors I follow
#signals — daily twitter-watcher digests
#inbox-alerts — flagged emails that need me
#to-do — assign agent tasks
#fitness — Zwift race analysis via Strava MCP
#glutenornot — uptime + Sentry errors for my app

Start with one #general channel. Add channels one at a time, as needed.

I started with just #general and layered channels on one at a time, mostly per-project. Strongly recommend starting small.

Each channel is a dedicated job queue or feed. This structure is what makes the next slide possible.

Information flows to me now

I stopped wading through the internet. What I want to know shows up in Discord.

  • inbox-watcher: reviews, catalogs, and prioritizes forwarded email — I get pinged only when something needs action
  • twitter-watcher: checks topics/accounts, filters noise, posts a short weekday summary to #signals
  • My personal agent sits in the same channels — I can task it to dig deeper on anything

Story: the inbox-watcher flagged that my Rosalía concert at MSG got rescheduled — action needed, caught without me watching email or chasing inbox zero. I check email much less now.

Example of compounding: a #signals post mentioned Claude Tag; I tasked Pi Pi to research how people are using it and bring findings back to the channel — without me ever logging into twitter.

One agent → two agents

  • Agent M1 lives on an old laptop: more power, more storage, room to experiment with local LLMs
  • More responsibility: read/write on my GlutenOrNot app, Sentry + Posthog MCPs, reviews and submits PRs — with guardrails
  • Shared memory in GitHub: each agent syncs every ~4 hours and reads across the same memory — one brain (ish)

Real moment: Agent M1 reviewed a PR that Pi Pi created to debug API failures on my app. Agents collaborating.

Another: away from my computer, Agent M1 helped debug why GlutenOrNot wasn't showing up in the EU (I hadn't signed the right forms) while Pi Pi concurrently helped with finance questions — all from my phone.

Setup: learn from my mistakes

  • Any always-on machine works — a Pi is cheap and low-power, but an old laptop is fine to start
  • systemd service broke repeatedly → run the session in tmux inside a while true loop so it respawns on crash or /exit
  • Enable loginctl enable-linger so tmux survives SSH disconnects
  • Tailscale for a secure tailnet between your devices — makes SSH trivial
claude --channels plugin:discord@claude-plugins-official

I first tried systemd with auto-restart and start-on-boot; it broke multiple times in the first few hours. With guidance from Opus I swapped to tmux + while-true loop. Just go with tmux.

Give the agent tools, skills, and MCPs the same way as any Claude Code session — SSH in, open the tmux session, configure as usual. Both my agents can read across all my GitHub repos.

Three learnings

  • Give it a real memory, not just a session. Less is more — only critical rules and active-project facts load every session; the rest is on-demand or archived.
  • Take security seriously. Agents see untrusted input (emails, Sentry errors). Minimal tool access, audit allow-lists, hardware keys on important accounts.
  • You will need to tinker. Not zero overhead — a restart every few weeks, a /clear of the context window about weekly.

Memory: everything in memory loads into context every session — if it grows too big, the agent misses the important stuff in the noise. Work with your agent to design it.

Security: more tools and permissions = bigger blast radius. Don't let agents act on instructions embedded in untrusted content. Audit permissions and channel access after the first week or two; expand permissions as trust grows, or they'll DM you constantly for approval.

Tinkering: over 3 months, restarted the Pi session twice; clear the 1M-token Opus context about weekly. Cost: fits in the $100 Claude Max plan; side projects use API keys with variable cost.

What's next

  • Reduce reliance on Claude alone — OpenRouter so agents stay online if Claude goes down
  • Local models for private data (financials, email) instead of cloud frontier models

Personal agents are here to stay. This is a better way of using the internet — I don't want to go back.
