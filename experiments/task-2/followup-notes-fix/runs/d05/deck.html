Go get yourself a
personal agent

Always-on AI assistants, and why every PM should build one

Open with the pitch: of everything I've experimented with this past year, personal agents are the most useful thing — and now the foundation I layer new projects on. Having an always-on assistant reachable from my phone or laptop has genuinely changed how I use the internet. This talk: what I built, how it works, what I learned, and how you can start.

The setup at a glance

  • Two always-on agents: Pi Pi (Raspberry Pi 5) and Agent M1 (old laptop)
  • One shared memory layer, synced through GitHub every few hours
  • Reached entirely from Discord — phone, laptop, anywhere
  • Runs inside a Claude Max plan ($100/mo), plus API costs for side projects

Orient the audience before any details. Two cheap always-on machines, one shared brain, Discord as the universal interface. Emphasize the cost point: this is not an expensive setup — an old laptop or a ~$80 Pi, plus a subscription many of us already have. No exotic infrastructure.

How it works: Claude Channels

Claude Channels wire a Claude Code session to a messaging app. The agent listens for new messages, crafts a reply, and responds right in the chat.

The session lives on an always-on machine — so the agent is reachable anytime, from anywhere.

Explain the mechanism simply: it's a Claude Code session with a plugin that listens to the messaging API (Discord DMs or channel posts), forwards messages to the agent, and posts the agent's reply back. Contrast with my earlier Openclaw experience — this is the same always-on idea but far more reliable. Key insight: the agent lives somewhere always-on, so you're not tied to your desk or SSH.

The killer workflow: idea → plan

I voice-dump a random idea from my phone. The agent researches it, writes a markdown plan, and commits it to git. I execute later from my laptop.

Ideas that used to die in emails-to-self and Notion now become real, high-fidelity plans.

This is the single most useful workflow I've found. My best ideas come while biking or walking the dog — my phone is the capture device. Don't be precious about voice-to-text accuracy; Opus/Sonnet parses messy input fine. The agent doesn't just start building — it researches and writes a plan into a plans folder in git. Before this, ideas went to email/scraps of paper/Notion and were forgotten. Now I execute them, delegate them to the agent, or deliberately archive them.

Discord channels = job segmentation

  • #questions — random questions
  • #reminders — scheduled reminders
  • #daily-briefing — weather + articles every morning
  • #signals — daily twitter-watcher digests
  • #inbox-alerts — flagged emails
  • #to-do — task assignments
  • #fitness — Zwift race analysis via Strava
  • #glutenornot — uptime + Sentry alerts for my app

Start with one channel. Add more only as needed.

I started with just #general and layered channels one at a time, mostly per-project. Strongly recommend starting small. Each channel is a dedicated job queue or feed — the channel list on the slide shows where it naturally grew to over a few months. The point for PMs: channels are a dead-simple routing and prioritization mechanism, no orchestration framework required.

Information flows to me now

Inbox-watcher

Reviews and prioritizes forwarded email. Flagged the rescheduled Rosalía concert at MSG before I'd ever have seen it.

Twitter-watcher

Reads topics/accounts I care about, posts a weekday digest to #signals. Twitter signal without twitter.

I check email far less. I never open twitter. The internet comes to me.

The behavioral shift: I used to check email incessantly and absentmindedly. Now dedicated agents watch inboxes and feeds, and only surface what needs attention. The Rosalía example is the concrete story — a rescheduled concert I had tickets for, flagged automatically, no inbox-zero chasing. Bonus pattern: my personal agent sits in the same channels these watcher agents post to, so I can task it to go deeper — e.g., I had Pi Pi research how people use Claude Tag to complement a #signals post, without ever logging into twitter.

Setting it up (learn from my mistakes)

  • Any always-on machine works — an old laptop is fine; a Pi is cheap and low-power
  • Run the session in tmux wrapped in a while true loop — it respawns itself on crashes
  • Enable loginctl enable-linger so the session survives SSH disconnects
  • Use Tailscale for a private, secure network between your devices
claude --channels plugin:discord@claude-plugins-official

Practical setup notes. I first tried systemd with auto-restart — it broke multiple times in the first few hours. tmux + while-true loop just works; go straight there. Lingering keeps tmux alive after SSH disconnects. Tailscale creates a private "tailnet" — a secure conference room for your devices — making SSH trivial. Add tools/skills/MCPs exactly like a normal Claude Code session: SSH in, attach to tmux, configure. Both my agents have GitHub access so they can read across all my repos.

One agent → two agents

  • Agent M1 (old laptop): more power, more storage, experiments with local LLMs
  • More responsibility: write access to my app, Sentry + Posthog MCPs, reviews/submits PRs with guardrails
  • Shared memory in GitHub, synced every ~4 hours — one brain (ish)

Real moment: Agent M1 debugged why my app wasn't showing in the EU while Pi Pi handled finance questions — concurrently, from my phone.

Why a second agent: the laptop has more compute and storage, and I wanted to tinker — the Pi is still going strong. Agent M1 gets permissions I wouldn't give the Pi, with guardrails on autonomous action. Fun detail: Agent M1 reviewing a PR that Pi Pi created to debug API failures — agents collaborating. The shared memory layer in GitHub means if one agent learns something, the other picks it up. The concurrent-help story is the payoff moment of the talk.

Three learnings

1. Give it a real memory — but less is more

Everything in memory loads into context each session. Load only critical rules and active projects; archive the rest.

2. Take security seriously

Agents see untrusted input (emails, error reports). Limit tool access, audit allow-lists after week one, use hardware keys.

3. Expect to tinker

Not zero overhead: ~2 restarts in 3 months, weekly context clear. Fits in a $100 Claude Max plan.

Memory: work with your agent to design it; if memory grows too big, the important stuff gets lost in the noise. Security: blast radius grows with every tool and permission you grant — agents must never act on instructions embedded in untrusted content, and no new access approvals except directly from me. I granted more permissions over time as I got comfortable, which also cut down constant permission-DMs. Tinkering: if the agent goes silent on Discord, it's usually a silent failure or dropped auth — SSH into tmux and restart. Weekly: /clear the 1M-token context window. Cost: Max $100 plan covers channels; side projects use API keys with variable cost.

What's next

  • Reduce single-provider reliance — OpenRouter so agents stay online if Claude goes down
  • Local models for private data (financials, email) instead of cloud frontier models
