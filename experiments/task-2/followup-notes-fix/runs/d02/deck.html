Internal PM Session

Go get yourself a
personal agent

What a year of running always-on AI agents taught me — and why they're now the foundation I build everything else on.

Open with the hook: of all the fun and wild stuff I explored this past year, personal agents are the most useful, the most interesting, and now the foundation I layer new projects on top of. Having an always-on, super-helpful assistant reachable from my computer, phone, wherever — has genuinely changed how I use the internet. Frame for PMs: this is a build-it-today talk, not a someday talk.
The Setup

At a glance

  • Two always-on agents: "Pi Pi" on a Raspberry Pi 5, "Agent M1" on an old laptop
  • One shared memory layer, synced through GitHub every few hours
  • Reached entirely from Discord — phone, laptop, anywhere
  • Runs inside a Claude Max plan, plus API costs for side projects
Quick orientation slide — don't dwell. The point: this is cheap, scrappy hardware. A Raspberry Pi and an old laptop. No fancy infra. Everything is reached through Discord, so the interface is just a chat app I already have on my phone. Cost framing: fits inside a Claude Max plan ($100 tier, not $200). Side projects like twitter-watcher use API keys with variable cost.
The Pitch

An always-on assistant, reachable from anywhere, changes how you use the internet.

Before this, my ideas went into emails to myself, scraps of paper, or Notion — forgotten and never revisited. Now: every thought, idea, question, or task goes to the agent, on the go or at home. Key PM takeaway: the value isn't any single feature — it's that the agent is always there, so capture and follow-through actually happen. A lot more of my silly ideas turn into high-fidelity plans I can execute, delegate, or deliberately archive.
How It Works

Claude Channels: an agent you can text

  • Wires a Claude Code session to a messaging channel — I use Discord
  • The agent lives on an always-on machine, not your laptop
  • It listens for new messages, crafts a reply, and responds right in the chat
  • No SSH, no being at your desk — reach it from wherever you are
Mechanism: the plugin has the agent listen to the messaging channel's API for new messages (a DM, or a post in a channel the agent is in), forwards it to the always-on session, and the agent replies in the messenger. Context: my first always-on agent experience was Openclaw — it learned and recalled my preferences, but I had real frustration with it (covered in my personal-context MCP writeup). Claude Channels is the same idea, done more reliably. Pi Pi runs on the same Raspberry Pi 5 I first used with Openclaw.
The First Agent

Pi Pi: capture → plan → execute

  • Voice-to-text from my phone — don't be precious about accuracy; Opus/Sonnet parses messy input fine
  • Best ideas arrive biking or walking the dog — the phone is the capture device
  • The killer workflow: the agent researches the idea and writes a plan in markdown → plans folder → committed to git
  • I pick it up from my laptop later and execute when ready
Emphasize the workflow, not the tech: the agent doesn't just start building — it does the research, writes the plan in markdown, dumps it into a plans folder, commits to git. Then I execute from my laptop "like a proper millennial." The before/after: ideas used to die in Notion or on paper. Now they become plans of much higher fidelity, and I can take them on, delegate them to the agent, or consciously throw them away. PM angle: this is a capture-to-execution pipeline with near-zero friction at the capture end.
Organizing the Work

One Discord channel per job

#questions · random questions #reminders · scheduled nudges #daily-briefing · weather + articles #signals · twitter-watcher digest #inbox-alerts · flagged emails #to-do · assign agent tasks #fitness · Zwift/Strava analysis #glutenornot · uptime + Sentry errors

Start with just #general. Add channels one at a time, as needed.

I started with a single #general channel and layered channels on one at a time, mostly per-project. Strongly recommend starting small. Examples worth narrating: #daily-briefing posts a report every morning; #fitness analyzes Zwift races from Strava URLs via the Strava MCP; #glutenornot gets uptime alerts and Sentry errors from my app. PM angle: channels are job segmentation — each one is a scoped queue with its own context, like lightweight routing.
The Behavior Change

Information flows to me — I don't chase it

Inbox-watcher

Reviews, catalogs, and prioritizes forwarded email. Alerted me that my Rosalía concert at MSG was rescheduled — without me watching email or chasing inbox zero.

Twitter-watcher

Checks topics and accounts I care about, judges what's worth reading, posts a weekday summary to #signals. Twitter signal without spending time on Twitter.

I used to check email incessantly and absentmindedly. Still do sometimes, but far less — task-dedicated agents on top of the channels helped me chill out. The composable part: my personal agent is present in the same channels these watcher agents post to via webhook. I tasked Pi Pi to dig into how people are using the new Claude Tag tool and bring findings back to the channel — complementing a #signals post — without me ever logging into Twitter. PM angle: this is pull → push. The interface inverts from "go wade through the internet" to "curated alerts arrive."
Build It Yourself

Setup: boring, reliable, cheap

  • Any always-on machine — a Raspberry Pi (cheap, low power) or an old laptop
  • Run the session in tmux wrapped in a while true loop — it respawns if it crashes. Learn from my mistakes: skip systemd, just use tmux.
  • loginctl enable-linger so the session survives SSH disconnects
  • Tailscale for a secure tailnet between your devices — makes SSH trivial
claude --channels plugin:discord@claude-plugins-official
War story: I first set up Claude Code as a systemd service with auto-restart and start-on-boot. It broke multiple times in the first few hours. With guidance from Opus I swapped to tmux + while-true loop — if it crashes or I /exit, it respawns. I'd heard of tmux from Steve Yegge's gas town writeup; this was the excuse to try it. Don't run this on a machine that turns off — that defeats the purpose; the agent disappears. You can also find the Discord plugin via the Discover tab in /plugins. Tools, skills, and MCPs are configured like any normal Claude Code session — SSH in, open the tmux session, connect things as usual. Both agents have GitHub access so they can read across all my repos.
Scaling Up

One agent → two agents, one brain (ish)

  • Agent M1 lives on an old laptop: more power, more storage, room to experiment with local LLMs
  • More responsibility: read/write on my GlutenOrNot app, Sentry + Posthog MCPs, reviews and submits PRs — with guardrails on autonomous action
  • Shared memory in GitHub: each agent syncs every ~4 hours, both read the same memory
  • Real moment: M1 debugged why GlutenOrNot wasn't showing in the EU (unsigned forms) while Pi Pi handled finance questions — concurrently, from my phone
The Pi is still going strong — the second agent was about tinkering and having the machine handy, not necessity. Nice anecdote if there's time: there's a screenshot of Agent M1 reviewing a PR that Pi Pi created to debug API failures on my app — agents reviewing each other's work. PM angle: specialization + shared memory is the coordination pattern. Access levels differ per agent based on trust and blast radius.
Learnings

Three hard-won lessons

  • Give it a real memory, not just a session. Less is more — everything in memory loads into context, so keep only critical rules and active-project facts; archive the rest.
  • Take security seriously. Agents see untrusted input (random emails, Sentry errors). Minimal tool access, audit allow-lists after week one, hardware keys on important accounts.
  • You will need to tinker. Not zero overhead: ~2 restarts in 3 months, plus a weekly /clear of the 1M-token context window.
Memory: work with your agent to design the memory system. If memory grows too big, the agent misses the important stuff in the noise. Ours loads only critical rules/active-project facts per session; everything else is on-demand or archived. Security: the more tools/MCPs/allow-list permissions, the bigger the blast radius. The agents must not act on instructions embedded in untrusted content, nor approve access requests from anywhere but me. As trust grew I granted more permissions — otherwise it DMs me constantly for things I'm fine with it doing (like reading a repo). Tinkering: not Openclaw-level repair work, but not zero. If the agent goes quiet on Discord, it's probably silently failing — SSH into tmux, restart Claude or re-auth. Cost: fine within Claude Max $100; side projects are API-key variable cost.
