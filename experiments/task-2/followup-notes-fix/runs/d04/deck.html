The most useful thing I built this year — and the foundation I now layer every new project on top of.

Open with the hook: of all the fun and wild stuff I explored this past year, personal agents are the most useful, the most interesting, and now the foundation for everything else I build.

Frame for PMs: this isn't a dev toy. It's a change in how I use the internet — an always-on, super-helpful assistant reachable from my computer, phone, wherever.

Promise of the talk: what it is, how I set it up, what surprised me, and why you should build one.

The setup at a glance

  • Two always-on agents — "Pi Pi" on a Raspberry Pi 5, "Agent M1" on an old laptop
  • One shared memory — synced through GitHub every few hours
  • Reached entirely from Discord — phone, laptop, anywhere
  • Runs on a Claude Max plan — plus API costs for side projects

Give the mental model up front so the rest of the talk lands: cheap always-on hardware, Discord as the interface, GitHub as shared memory.

Emphasize the accessibility point: I talk to these agents the same way I text a friend. No SSH, no special tooling on my phone.

Cost question always comes up — preempt it: fits inside the $100 Claude Max plan; side projects use API keys with variable cost.

How it works: Claude Channels

Claude Channels wire a Claude Code session to a messaging channel — so the agent lives on an always-on machine and you reach it from anywhere.

  • Agent listens to the messaging API (Discord DM or channel post)
  • Message is forwarded to the always-on session
  • Agent replies right in the chat

Explain the mechanism simply: the plugin watches Discord for new messages, forwards them into the Claude Code session, and the agent's reply comes back in the chat.

Backstory: Openclaw was my first always-on agent — it learned and recalled my preferences, but I was constantly repairing it. Channels gave me the same always-on reach with far less fragility.

Key point for PMs: the "product" here is reachability. The agent being in the same place I already talk to people is what makes it stick.

The first agent: Pi Pi

Every thought, idea, question, or task — on the go or at home — goes to Pi Pi.

  • Mostly voice-to-text from my phone — sloppy is fine, the model parses intent
  • Best ideas happen biking or walking the dog — the phone is the capture point
  • Killer workflow: agent researches the idea, writes a plan in markdown, commits it to git — I execute later from my laptop

Contrast with the old behavior: emailing myself, scribbling on paper, dumping into Notion — forgotten and never revisited.

Now silly ideas turn into high-fidelity plans. I can execute them, delegate them to the agent, or consciously archive them. The ideas stop dying.

Tip for the room: don't be precious about voice-to-text accuracy. With Opus or Sonnet underneath, the agent figures out what you meant.

Discord channels = job segmentation

Start with #general. Add channels one at a time, mostly per project.

  • #questions — random questions
  • #reminders — scheduled reminders
  • #daily-briefing — weather + articles daily
  • #signals — twitter-watcher digests
  • #inbox-alerts — flagged emails
  • #to-do — assign agent tasks
  • #fitness — Zwift race analysis via Strava
  • #glutenornot — uptime + Sentry alerts

Design lesson: I started with a single #general channel and layered channels one at a time. Strongly recommend starting small and adding as needed — don't architect the whole org chart on day one.

Each channel is a job. Some are inbound (alerts, briefings), some are outbound (to-do, questions). The channel list reads like a product surface area.

PM framing: this is information architecture for a one-person company. Channels are how I scope an agent's attention.

Information flows to me now

I stopped wading through the internet. The internet comes to my Discord.

  • inbox-watcher reviews and prioritizes forwarded email — flagged a rescheduled Rosalía concert at MSG before I'd ever have seen it
  • twitter-watcher reads Twitter so I don't have to — posts daily summaries to #signals
  • Pi Pi sits in the same channels — I can task it to dig deeper on anything that shows up

Behavior change story: I used to check email incessantly and absentmindedly. The inbox-watcher broke that loop — I only hear about email when it needs action.

Rosalía example is the most concrete — a rescheduled concert I had tickets to, flagged immediately, no inbox-zero chasing required.

The compounding move: my personal agent is present in the same channels the watcher agents post to. I asked Pi Pi to research how people use Claude Tag to complement a #signals post — without ever logging into Twitter.

Setting it up (learn from my mistakes)

  • Any always-on machine works — a Raspberry Pi is cheap and low-power; an old laptop is fine
  • systemd service broke within hours → tmux + while true loop so the agent respawns itself
  • loginctl enable-linger so tmux survives SSH disconnects
  • Tailscale for a private tailnet between your devices
claude --channels plugin:discord@claude-plugins-official

Confess the mistake: I first ran the session as a systemd service with auto-restart — it broke multiple times in the first few hours. Opus suggested tmux with a while-true loop; if it crashes or I /exit, it respawns. Just go with tmux.

Lingering matters: without loginctl enable-linger, the tmux session dies when you disconnect SSH.

Tailscale is badass — a "secure conference room" tailnet, inaccessible from the public internet. Makes SSH into the Pi and other devices trivial.

Tools/skills/MCPs are configured like any normal Claude Code session — SSH in, open the tmux session, connect things. Both agents have GitHub access so they can read across all my repos.

One agent → two agents

Pi Pi · Raspberry Pi 5

Personal assistant. Plans, questions, reminders, research. The daily driver.

Agent M1 · old laptop

More power, more storage, more trust. Write access to GlutenOrNot, Sentry + Posthog MCPs, reviews/submits PRs with guardrails.

  • Shared memory in GitHub — each agent syncs every ~4 hours, both read the same memory
  • They work together: Agent M1 reviews PRs that Pi Pi creates

Why a second agent: the laptop has more power for research tasks, more storage, and lets me experiment with local LLMs. The Pi is still going strong — I just wanted to tinker.

Trust gradient: Agent M1 got responsibilities I wasn't willing to give the Pi — write access to my app, Sentry and Posthog MCPs, with guardrails on autonomous action.

Best anecdote: away from my computer, Agent M1 debugged why GlutenOrNot wasn't showing in the EU (unsigned forms) while Pi Pi concurrently helped with finance questions — all from my phone.

Learnings

  • Give it a real memory, not just a session. Less is more — only critical rules and active-project facts load every session; the rest is on-demand or archived.
  • Take security seriously. Minimal tool access, audit allow-lists after week one, never act on instructions embedded in untrusted content. Hardware keys on important accounts.
  • You will tinker. Not zero overhead — restarts are rare, but expect a /clear of the context window about weekly.

Memory: everything in memory loads into context every session — if it grows too big, the agent misses the important stuff in the noise. Work with your agent to design the memory system.

Security: these agents see untrusted input — random emails, Sentry errors. They must not act on embedded instructions or approve access requests from anywhere but me. Blast radius grows with every tool and permission. I granted more permissions over time as I got comfortable — otherwise it DMs me constantly for approval.

Tinkering reality check: over 3 months, restarted the Pi session twice; clear the 1M-token Opus context roughly weekly. If the agent goes silent on Discord, it's usually auth dropped — SSH in and restart.
